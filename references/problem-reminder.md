# 三次失败复查提醒

总 skill 与各子 skill 共用 [problem_reminder.py](../scripts/problem_reminder.py)。这是由助手显式调用的本地计数工具，不监听聊天、不定时后台运行、不自动制造新工具。

在用户明确授权本地留存后，可将问题摘要集中保存到本机总 skill 的 `private/problem-reminder/issues.json`，供后续任务查找复用。它不替代任何子项目的正式任务板、研究记录或项目绑定；也不会自动创建反馈包、上传或提交版本库。安装包不含问题库。首次提交时创建空库，不自动补录历史问题；未获授权时不要新建或写入问题库。

## 触发规则：助手负责调用

1. 开始相关任务或排查问题时，先运行`list`；按验收条件和相关环境判断是否已有同一问题，需要时`show`。不要只按标题合并不同环境的问题，也不要因换方案另建问题来清零。
2. 对需要修复的问题，先明确验收条件和相关环境，再`submit`；已有问题复用ID。记录必要的方案、结果和证据，不复制整段对话。
3. 修复但未验证时记`pending`；实际验证未通过或用户明确反馈“仍然不行”时记`failed`；完整验收通过才记`passed`。格式/路径检查不能代替用户端显示、点击等行为验证。
4. 同一轮累计三次失败，进入`needs-review`。继续试改前先向用户简要汇总失败方案与证据，复查验收条件、环境和验证缺口，再选择最小复现、补齐条件、使用已有工具或按需工具化。不要自动规定必须新建工具。
5. 第三次是最迟复查点；证据已表明方向不对时可提前复查。工具只计数并输出提醒，不强制阻断shell；助手必须遵循此规则。

提醒示例：“同一验收条件已至少三次失败。先暂停无新证据的试改，汇总方案与证据，复查环境和验收条件；再选择复现、补齐条件或按需工具化。”

## 最小调用

从总 skill 所在目录运行；子 skill 定位已安装总 skill 的实际目录调用，不复制脚本：

```bash
python3 scripts/problem_reminder.py list
python3 scripts/problem_reminder.py submit sample-issue --title '示例问题' --criterion '明确的验收条件' --environment '相关阅读器或系统'
python3 scripts/problem_reminder.py record sample-issue --event-id attempt-1-check --result failed --approach '尝试方案' --evidence '实际验证结果'
python3 scripts/problem_reminder.py show sample-issue
```

只有`submit`、`record`写库；`list`、`show`只读。`list`默认显示未解决问题，`list --all`包含已解决问题。用全局参数`--store /path/to/issues.json`可指定独立库，用于合成验证。

`event-id`标识一次结果观察，重试提交同一观察时复用该ID，避免重复计数。同ID内容不同会报错，不覆写历史。一次改动的“待验证”和稍后的实际验证是两次观察，使用不同ID，例如`attempt-1-pending`和`attempt-1-check`。

## 状态和计数

| 记录结果 | 本轮失败次数 | 状态 |
|---|---|---|
| pending：尚未验收 | 不变 | pending；已达三次则仍为needs-review |
| failed：验证失败 | 加1 | open；达到三次则为needs-review |
| passed：完整验收通过 | 清零 | resolved，历史仍保留 |
| 同观察重复提交 | 不变 | 不变 |

更换方案、解释原因或新增工具不会清零。复查后仍未验收通过，保留计数；发生新失败或再次查询仍可提醒。已解决问题复发时复用原问题ID，自动开启新轮次；不同验收条件或环境用不同ID。同验收条件和环境的重复提交会被拒绝。

每条问题保存ID、标题、验收条件、环境、状态、当前轮次、失败次数和事件历史；每个事件保存观察ID、方案、结果、证据与记录时间。记录时间不是对历史实际发生时间的推断。

## 安装和检查边界

工具仅依赖Python标准库，本机Linux/WSL用`fcntl`锁避免并发重复计数，临时文件替换保存；不支持直接用原生Windows Python运行。JSON损坏或版本不符时失败，不覆盖原库。退出码0表示命令完成，1表示输入或存储错误；出现提醒仍返回0，调用者须读取状态与提醒。

通过合成样例检查第三次提醒、问题间隔离、同观察重复/并发去重、待验证不清零、通过关闭、复发新轮次和坏库不覆盖。脚本无法判断用户是否满意，也不能自行证明验收条件满足；事实判断与提交由助手承担。

这是本机已安装总 skill 的扩展，不表示远程框架已发布新版本。共享问题库是当前用户明确授权的本地操作记录例外，不允许因此更改其他项目authority或自动导出真实反馈。
