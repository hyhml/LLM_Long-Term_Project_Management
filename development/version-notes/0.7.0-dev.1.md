# 0.7.0-dev.1

Development implementation of the accepted human-readable project-map feature request.

## Runtime changes

- The deterministic renderer writes both `views/project-map.json` and `views/project-map.md` from the same formal inputs and revision.
- JSON remains the compact directly loaded child view. Markdown is an on-demand human-review view and explicitly states that it is derived and non-authoritative.
- Markdown summarizes objective and standards, current focus, high/low tasks, formal records grouped by kind, sources, relations, navigation, current revision, and the receipt directory.
- The validator detects stale or manually edited Markdown when present. A compatible child created before this version may temporarily lack Markdown; the next explicit render or accepted transaction creates it without a project-data migration or revision increment.
- Transaction publication and receipts include the Markdown view alongside the JSON view.

## Boundaries

- Project-data schemas, entry protocol, handoff format, and feedback format are unchanged.
- The renderer does not read pending `work/`, infer a latest-change summary from receipts, or generate Mermaid.
- The real feedback package remains external; repository tests contain only the accepted synthetic invariant.

## Validation record

The accepted synthetic feature contract was exercised without copying the external report into the repository. All 43 developer tests passed once after runtime source freeze, including deterministic dual rendering, representative human-review sections, pending-work exclusion, JSON and Markdown manual-edit detection, a simulated pre-0.7.0 child committing successfully, transaction receipt coverage, and the runtime allowlist contract. The development skill also passed the `skill-creator` structural validator.

This is development-only evidence. No user runtime release or installed-skill update has been performed.
