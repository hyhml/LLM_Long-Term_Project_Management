# 0.3.0-dev.1

Development prerelease implementing accepted ADRs 0003–0007.

## Changed

- Project identity is now an explicit stable objective contract with scope, assumptions, evidence standard, and completion standard.
- Formal data is split among `state/`, `records/`, and `sources/`; maps and indexes remain derived.
- Task priority/status moved to `state/task-board.json`; the canonical project revision moved to `state/project.json`.
- Record-store schema advances to `ltpm-record-store/v2`; map-view schema advances to `ltpm-project-map-view/v2`.
- Handoff `base_revision` now binds to `state/project.json.revision`.

## Added

- Separate semantic record kinds for claims, evidence, attempts, reviews, and decisions, with namespaced domain extensions.
- Validation requirements for reusable failed-attempt records and rejection of transient dump kinds.
- A candidate-based project transaction tool with stale-base checks, one revision advance, validation, publication, rollback within the running process, and receipts.
- `sources/registry.json` and `index/manifest.json` with explicit authorization and coverage boundaries.
- A lightweight formal-metadata search tool that always reports coverage and never equates an empty result with project-wide absence.

## Compatibility and limits

- This is a breaking development schema change for newly generated child skills.
- Existing v0.1 and v0.2 development child skills are not migrated automatically.
- The workflow transaction is not crash-atomic. Immutable snapshots and atomic `HEAD` remain proposed in ADR-0001.
- Source-content extraction, domain-specific evidence grading, parallel merge, and automatic index building are not included.
