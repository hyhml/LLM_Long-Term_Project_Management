# 0.6.2

Project-skill discovery and transaction-candidate isolation fix.

## User-visible changes

- Project initialization reports whether the new child is discoverable from the current Codex working directory. If not, it reports the project root for a new session and the explicit `$skill-name` invocation.
- Children remain project-local; initialization does not create a user-level copy or symbolic link.
- Transaction candidates no longer contain a `SKILL.md`, and successful commits remove their candidate directory while preserving plans and receipts.
- Older committed candidates can be identified with `cleanup-preview` and removed only with `cleanup-committed` bound to the exact approved preview hash. A later content or scope change invalidates that approval.

## Compatibility

Entry protocol 1, all project-data schemas, and package schemas are unchanged. Existing compatible children require only `refresh-runtime`; no adapter or project-data migration is required. Legacy candidate cleanup remains a separate user-approved maintenance action.
