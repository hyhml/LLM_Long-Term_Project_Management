# 0.5.0-dev.1

Development implementation of ADR-0013 and the approved v0.5.0 project-isolation plan.

## Changed

- New children are thin explicit adapters with `ltpm-project-instance/v1` instead of copied conditional framework protocols.
- `project-instructions.md` is a project-owned boundary preserved across adapter updates.
- A shared binding inspector checks canonical root, immutable project identity, revision, entry protocol, data schemas, duplicate identity, and managed adapter hashes.
- Search, rendering, formal transactions, and handoff export use the shared project binding; legacy or incompatible children remain readable while formal writes fail closed.
- Handoff destination checks reject cross-project integration and report stale revisions.
- Ordinary conversations use one active project binding and never switch silently.
- Explicit cross-project coordination reads compact maps, reports coverage, and forbids merged writes.
- The v0.4.0 adapter upgrader implements inspect, proposal, itemized decisions, staged validation, publication/rollback, prior-adapter archive, and receipt without changing project revision.

## Data and compatibility boundary

- Project state, task, record, source, view, index, and handoff schemas do not change from v0.4.0.
- No general project-data migration is performed; `migration-required` blocks formal work pending a separate future migration design.
- Existing v0.4.0 children require an accepted thin-adapter upgrade before formal writes.
- No real project, regression, evaluation, private-user, or machine-profile data is included.
