# 0.7.0

Human-readable project map release.

## User-visible changes

- New projects and accepted transactions generate both `views/project-map.json` and `views/project-map.md` from the same formal project revision.
- JSON remains the compact directly loaded machine/LLM map. Markdown is loaded only for human review and summarizes objective and standards, current focus, high/low tasks, grouped formal records, sources, relations, navigation, revision, and the receipt directory.
- Both views identify themselves as derived and non-authoritative. The validator rejects stale or manually edited generated views.
- Existing compatible children remain valid without the Markdown sibling. The next explicit render or accepted transaction creates it without a project-data migration or an extra revision increment.
- The first version does not infer a latest-change summary from receipts and does not generate Mermaid.

## Compatibility

Entry protocol 1, project-data schemas, handoff schema, and feedback schema are unchanged. Existing children need only the updated shared runtime; no adapter or project-data migration is required.
