# 0.6.1

Lightweight interaction update for environment discovery, packaging consent, and priority semantics.

## User-visible changes

- One approval now covers bounded tool discovery and private machine-profile save.
- `.llmpack` export requires approval of a preview bound to its project, revision, inputs, and destination.
- Ordinary current-context feedback needs one final preview approval; new private or external reads add one earlier bounded permission.
- Feedback remains `ltpm-framework-feedback/v1`, and handoffs remain `llm-long-term-project-handoff/v1`.
- Framework loading, foreground/background task scheduling, and objective/milestone/task hierarchy are explicitly separate.

## Compatibility

Entry protocol 1, existing project-data schemas, existing compatible children, and both v1 package formats remain supported. No child adapter or project-data migration is required.

## Validation record

The new tests first reproduced direct unapproved handoff export, missing approved initialization, and absent structured priority semantics on the v0.6.0 behavior. During implementation, the first targeted run exposed a handoff manifest variable error in the new export path; it was corrected before the complete suite. All 38 developer tests then passed.
