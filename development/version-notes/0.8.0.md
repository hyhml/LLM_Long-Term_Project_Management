# 0.8.0

Research content trees guide task planning, and the project map focuses on confirmed tasks.

## User-visible changes

- Research projects may keep one accepted content tree with questions, dependencies, evidence assessments, and open gaps. Tasks can cite tree nodes and state the evidence needed to accept their results.
- The project map shows the objective, accepted tasks, and a link to the content tree when one exists. Ordinary research records and sources remain in formal storage for selective reading.
- Tree changes and candidate tasks require separate user decisions. Completing a task does not automatically close a research gap or change an evidence assessment.
- A concise glossary defines LTPM, the total and child skills, the content tree, the project map, the task board, and formal records.

## Compatibility

The content tree is optional. Existing project data and revisions are unchanged by the framework update. A previously generated all-record map remains valid until an explicit view rebuild or accepted transaction regenerates the task-focused map. Project-data schema identifiers remain unchanged.

## Validation

The release receipt records the final test, artifact, publication, and remote confirmation evidence.
