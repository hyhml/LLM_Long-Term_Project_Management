# 0.2.0-dev.1

Development prerelease implementing accepted ADR-0002.

## Changed

- Formal accepted state moved from an authoritative project map to `records/store.json`.
- `views/project-map.json` is now a deterministic, directly loaded derived view.
- Pending exploration and candidate tools live under `work/`; they enter `records/` only through itemized proposal and user-confirmed commit.
- Handoff export binds `base_revision` to the formal record-store revision.
- Generated child-skill instructions enforce separate explorer and integrator write boundaries.

## Added

- `scripts/render_project_views.py` for deterministic map generation.
- Validator detection of stale or manually edited derived maps.
- ADR-0002 documenting the accepted storage boundary and its limits.

## Compatibility

- New projects generated from this development version use record-store schema `ltpm-record-store/v1` and map-view schema `ltpm-project-map-view/v1`.
- `.llmpack` remains schema version 1.
- Existing v0.1 child skills are unchanged. No automatic migration is included.
- ADR-0001's immutable snapshots, content addressing, atomic `HEAD`, and parallel merge remain proposed.
