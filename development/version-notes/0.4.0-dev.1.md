# 0.4.0-dev.1

Development prerelease implementing accepted ADR-0009 and ADR-0010.

## Changed

- Classification is now a continuous project-control input rather than a one-time opening disclosure.
- Material work is classified by layer, data subtype, and audience, then routed by explicit authority, storage, validation, version, and release controls.
- Data subtypes distinguish project, regression, evaluation, environment, and private-user material.
- Formal task contracts use `ltpm-task-contract/v1` and must be `data:project` with a complete control plan.
- Project state advances to `ltpm-project-state/v2`; the generated map advances to `ltpm-project-map-view/v3`.
- Developer regression policy defines six core invariant groups, proposal triggers, test-change order, and the boundary between framework tests and external datasets.

## Data and distribution boundary

- Test code and safe synthetic fixtures may live with framework development.
- No real regression cases, retrieval evaluation sets, historical failure corpora, standard answers, or private machine/user data are included.
- Domain-specific educational adversarial testing remains outside the current scope.
- Existing `0.3.x` child projects are not migrated automatically.
- This prerelease remains on `development`; `main` is unchanged until an explicit runtime release.
