# 0.6.0

Stable release of the consent-based runtime-to-developer framework feedback loop.

## User-visible changes

- A user-raised problem that may involve the framework now triggers provisional classification even before reproducibility or root cause is known.
- Local evidence collection and final export are separate consent gates.
- Export approval covers each content section and every attachment.
- `.ltpm-feedback` is a single integrity-checked file distinct from project `.llmpack` handoffs and is never uploaded automatically.
- Runtime inspection reports evidence coverage, redaction, provisional classification, retention scope, and the fact that integrity is not truth or authenticity.
- Existing v0.5.0 thin child skills remain compatible and obtain the shared protocol from the updated total skill; newly generated children also include an explicit feedback route.

## Developer boundary

- Developer intake verifies and summarizes untrusted packages, refuses repository quarantine, does not execute attachments, and requires completed itemized triage before a resolution receipt.
- Real feedback, triage material, and historical incidents stay outside the repository and runtime release.
- Synthetic test derivation and long-term retention cannot exceed the user's recorded authorization.
