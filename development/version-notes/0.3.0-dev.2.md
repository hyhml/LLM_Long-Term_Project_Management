# 0.3.0-dev.2

Development prerelease implementing accepted ADR-0008.

## Changed

- Every substantive managed request now begins with an explicit change-layer and audience classification.
- Change layer is one of `project-data`, `framework`, `mixed`, or `none/read-only` and is determined by the authority actually changed.
- Audience is one of `runtime-user`, `developer`, or `both` and is determined by who consumes and receives the result.
- Mixed changes must be split before editing; final handoffs report where each class was written, versioned, and released.
- Generated child skills route framework changes to explicit framework development mode instead of applying them as project-data edits.

## Compatibility and distribution

- No project storage or handoff schema changed from `0.3.0-dev.1`.
- Existing child skills are not modified automatically; newly generated child skills contain the classification rule.
- This development commit includes both future runtime behavior and developer-only ADR/version material. It remains on `development` until an explicit runtime release to `main`.
