# Version plan: 0.6.0 consent-based framework feedback

- Status: Released as `v0.6.0` on 2026-09-22
- Plan date: 2026-09-22
- Change class: `framework` plus external `data:regression` boundary
- Audience: `both`
- Primary ADR: ADR-0014
- Requirements: `FEED-001`–`FEED-008`

## Objective and completion standard

Before sustained real-case testing, let any compatible child route a user-raised possible framework problem into a privacy-minimized, separately approved, single-file report. Let the developer verify and quarantine that report outside the repository, triage it without treating it as truth, propose only authorized synthetic tests, and return a non-mutating resolution receipt.

Completion requires deterministic tests for both consent gates, exact attachment authorization, safe archive handling, external-only developer quarantine, runtime/developer release separation, and receipt linkage. There is no automatic upload, real-case repository storage, or implicit project update.

## Compatibility

The shared total-skill protocol is compatible with entry protocol 1. Existing v0.5.0 thin children can use it without rewriting project data or the adapter. Newly generated children include a concise route to improve discovery. No project data schema changes.

## Release boundary

Runtime: feedback reference, schema, exporter/verifier, total-skill routing, and generated-child discovery line.

Developer-only: ADR, product map, intake/quarantine/triage/receipt harness, policies, version material, and synthetic tests.

External: all real feedback packages, attachments, triage records, and retained historical incidents.
