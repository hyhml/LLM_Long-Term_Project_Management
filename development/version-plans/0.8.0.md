# Version plan: 0.8.0 tree-guided task map

- Status: Development implementation; stable release pending
- Requirement: `DATA-014`, with task and authority boundaries from `DATA-003`, `DATA-004`, `FLOW-005`, and `GOV-009`
- Decision: ADR-0016

## User-visible result

The directly loaded project map and human-review map show the objective, confirmed tasks, and an optional research content tree entry. For research projects, one accepted tree artifact holds question nodes, evidence assessments, dependencies, and gaps. Candidate tasks cite tree nodes and intended acceptance evidence; user confirmation remains required before task-board changes. A concise glossary defines the total skill, child skill, map, tree, board, and formal records.

## Compatibility

Project-state, record-store, task-board, source-registry, handoff, and project-map schema identifiers stay unchanged. The new map is a selective projection supported by the existing `nodes` shape. Old all-record maps remain valid only if they match the deterministic prior projection; an explicit view rebuild or accepted transaction replaces them. Existing project facts and revisions do not change merely because the framework updates. The tree is optional, so ordinary projects need no migration.

## Evidence gates

1. Synthetic feature tests: valid tree, task link, unknown node, cycle, map filtering, no automatic board mutation, accepted transaction, old-view rebuild.
2. Core invariant and release-boundary tests; skill and JSON validation.
3. Exact allowlist runtime build, runtime skill validation, and generated-child smoke test before local installation or public release claims.
4. If published, follow the runtime release policy for `main`, tag, archive, remote confirmation, and receipt. Local development validation alone is not publication.
